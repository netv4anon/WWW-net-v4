# 当前输入契约勘误

旧WWW评测说明把9槽输入描述为“中心加8个邻居”，该解释有误。两份原NPZ的`spatial_volumes`形状均为`(33076,8,24)`，其中第0槽就是中心序列。旧评测将`volume_sequences`再拼到前面，因此便携history/future为`(33076,12,9)`，语义如下：

| 评测输入槽 | 来源 | 可确认身份 |
|---|---|---|
| 0 | `volume_sequences` | CSV保存精度下的中心序列；预测评分目标使用此槽 |
| 1 | `spatial_volumes[:,0,:]` | 同一中心在空间数组中的保存表示 |
| 2–8 | `spatial_volumes[:,1:8,:]` | 其余7个空间槽；完整道路身份与时间同步尚未恢复 |

两种中心表示在生成数据中存在两位小数量化差异，最大绝对差0.0050048828125；混合快照12608条观测标签控制行两槽完全相同。不能把槽0/1当作两条独立道路，也不能因此推断输入包含了未来目标。

旧`RidgeLocal9`仍表示历史中使用这9个数值槽的原配置，名称和保存结果不改写；它不表示9条独立道路。旧STID训练对9槽共享参数和损失，其中包含中心的重复表示；其中心推理经核验仅依赖中心输入。固定权重的输入独立性不能证明改变槽数后重新训练的结果不变。

本轮新增`RidgeCenterPair`（槽0/1）和`RidgeWithoutCenterCopy`（槽0/2–8），只是固定输入敏感性检查。其余7槽的身份未恢复，第二种配置也不能被包装成已验证的8道路空间预测。

原归档和结果作为历史版本保留。当前使用应同时读取本勘误及`CURRENT_EVALUATION_CONTRACT.json`；原归档中“eight relative neighbor slots”的说法由此修正。原始数组、索引、旧预测和八张主表未被替换。

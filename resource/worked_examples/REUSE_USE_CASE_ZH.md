# 使用示例二：事件记录唯一是否足以保证序列未复用？

读者需要先声明预测输入单位，再判断“测试交通未在训练中出现”。本例从原 NET-V4 快照开始，随后把同一检查用于单独标识的 IGSTGNN Contra_Costa v1 发布物；两项结果属于不同总体。

原 NET-V4 保留完整测试查询。Mixed 的中心历史键命中 102 个查询，74 个还重复了训练未来；Generated 没有命中，两快照的完整九槽历史键均没有命中。Mixed 的 LastValue 全测试 MAE 30.1601→30.1239，收益只有 0.12%，所有命中均为控制，因此不能用它解释事件预测优势。40 个常数目标命中组从 0→3.6519，67 个冲突训练未来命中组从 2.0060→3.6727：不利结果必须同时报告。常数与冲突分组有重叠，计数不能相加。

这使检查单位和作用量级成为明确的读者决定。原快照的零完整九槽命中，仅支持这个字节键下的未匹配，不认证物理独立或时间独立。中心命中则支持有限的检索后果，不证明 STID 使用了查表。相应证据和见证位于 `components/netv4_checks/saved_lookup`；运行 `replay netv4_checks` 可从包内原快照重放，完整命令见读者指南。

以下外部示例检查固定的 Contra_Costa v1 文件及其 3909/837/839 切分。它说明完整事件记录唯一，可以与可利用的交通序列复用同时成立；其更大检索收益不能当作 NET-V4 自身的结果。

|检查/评分单位|获得的判断|
|---|---|
|完整事件记录|跨训练/测试完整记录重复为零，仍不足以判断交通输入独立|
|全网络交通历史与未来|839 个测试行中有 93 行与训练匹配，历史检索可取得完全相同未来|
|全网络目标支持排除之后的同站点流量历史|查表 MAE 仍改善 4.97%，说明检查粒度仍影响结论|
|严格站点流量历史排除|51/496 个站点训练视图为空，不能把排除结果称作完成时间修复|

已有 LastValue 与 ExactHistory 保存预测先于评分封存。保存的逐行误差给出总测试 MAE 16.166514 → 14.260033，改善 11.79%；全部收益来自 93 个命中行，这些行检索误差为零。其余 746 行的两种预测误差完全相同。检索查询只用历史，取回的是训练目标；它没有从测试目标读出答案。

检查单位会改变读者的可报告结论：事件记录唯一，可以同时存在可利用的预测序列重复。全网络目标状态排除后，针对单站输入的查表收益仍在；扩大到流量历史严格排除又会产生空训练支持。加入日历可以保留支持，但仍有流量-only 重复，且不是已恢复的真实时间切分。

这一示例让读者报告具体匹配单位、命中/未命中组和排除后的支持，而不是把“没有完整记录重复”或“一个范围重复为零”当成可靠泛化的证据。示例不推出原作者神经模型成绩虚高 11.79% 或 4.97%；数字只对应本例检索规则。相同数值也没有证明同一物理观测。
